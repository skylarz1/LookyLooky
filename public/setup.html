Why HTTPS

Full-motion video is decoded in the browser with WebCodecs, and browsers only offer WebCodecs on a secure page: HTTPS, or localhost. Opened over plain HTTP on a LAN address, the pages still work but every pane is a JPEG thumbnail with no sound.

LookyLooky serves HTTPS on its own (port [LookyLooky.SecurePort]) with a certificate from a small certificate authority it created for itself. Install that authority on each viewing device once and the secure pages open with no warnings:

Download the certificate (ca.crt) Open the secure dashboard

iPad / iPhone (Safari)
  1. Open this page in Safari and tap Download the certificate. Allow the download ("This website is trying to download a configuration profile").
  2. Open Settings → Profile Downloaded (near the top; or General → VPN & Device Management) → Install, and enter the passcode.
  3. Then Settings → General → About → Certificate Trust Settings and switch on LookyLooky Local CA. This second step is the one that is easy to miss.
  4. Open . iPad 6th gen and other devices on iPadOS 16.4–17 get full-motion video, with sound sent to them as PCM (they have no audio decoder for the usual stream). Tap a pane once to allow sound.
Android (Chrome)
  1. Download the certificate. Settings → Security → Encryption & credentials → Install a certificate → CA certificate, pick the file.
  2. Open the secure address.
Windows (Chrome / Edge)
  1. Download and open ca.crt → Install Certificate → Local Machine → Place all certificates in the following store → Trusted Root Certification Authorities.
  2. Restart the browser and open the secure address.
macOS
  1. Download and open ca.crt (Keychain Access opens). Double-click LookyLooky Local CA → Trust → When using this certificate: Always Trust.
Linux / kiosk Chrome
  1. sudo cp lookylooky-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates; for Chrome also import it under Settings → Privacy and security → Security → Manage certificates → Authorities.
  2. A kiosk that cannot install certificates can instead be started with --unsafely-treat-insecure-origin-as-secure=http://HOST:PORT --user-data-dir=/tmp/kiosk.

The certificate covers these names: . If you reach the box by another name or IP (e.g. its LAN address from the Docker host), add it to LOOKY_HOSTNAMES and restart — the server certificate is reissued from the same authority, so devices do not need to install anything again. Behind a reverse proxy that already does HTTPS, none of this is needed.

Pages

  • Dashboard — manage cameras and layouts, watch any layout.
  • View-only board — /camera-view.html?layout=<id or name>, for wall displays.
  • Camera wall — one main pane over six previews; /wall.html?layout=<id or name>.
  • Per camera: /stream/<id>/mjpeg, /stream/<id>/snapshot (also over plain HTTP, for other tools).
